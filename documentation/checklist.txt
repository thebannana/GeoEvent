GEOEVENT MICROSERVICES CHECKLIST
=================================


CLEAN ARCHITECTURE
------------------
- Every service follows the same 4-layer structure: Domain > Application > Infrastructure > API
- Domain layer has zero dependencies on other layers (no EF Core, no ASP.NET)
- Application layer depends only on Domain - no infrastructure imports
- Infrastructure layer implements Application interfaces - no business logic lives here
- API layer only calls Service interfaces - never repositories directly
- No circular dependencies between projects


CODE CONSISTENCY
----------------
- All services use identical folder structure (Entities, DTOs, Interfaces/Repositories, Interfaces/Services, Repositories, Services, Persistence/Configurations, Controllers, Middleware, Extensions)
- All services use ServiceResult<T> as the return type from service methods
- All services use PagedResult<T> for paginated responses
- All DTOs follow consistent naming: CreateXDto, UpdateXDto, XResponseDto, XFilterDto
- All controllers follow consistent naming: XController with route api/x
- All controllers return consistent error shape: new { error = result.Error }
- All DbContext classes use => Set<X>() pattern for DbSet properties
- All EF configurations live in separate IEntityTypeConfiguration<T> classes
- All services register dependencies via a static AddInfrastructure() extension method
- appsettings.json structure is identical across all services (ConnectionStrings, Jwt, Logging)


SECURITY
--------
- All controllers that require authentication have [Authorize] attribute
- JWT validation parameters are consistent across all services (Issuer, Audience, Key)
- ClaimsPrincipalExtensions.GetUserId() is used everywhere instead of raw claim parsing
- No secrets or connection strings are hardcoded - all read from IConfiguration
- SecurityHeadersMiddleware is registered in every Program.cs (X-Content-Type-Options, X-Frame-Options, X-XSS-Protection, Referrer-Policy)
- ExceptionMiddleware is registered in every Program.cs - no raw exceptions leak to clients
- All user-owned resources verify ownership before returning or mutating data (e.g. message.RecipientId != userId returns 403)
- Input DTOs use [Required] and [MaxLength] data annotations
- No sensitive data (passwords, tokens) included in response DTOs


DATABASE AND EF CORE
--------------------
- Every entity has a primary key configured via .HasKey()
- All string properties have .HasMaxLength() defined
- All required properties use .IsRequired()
- Indexes are defined on all foreign key and frequently queried columns
- Soft delete pattern is consistent (IsDeleted, IsDeletedByX) where applicable
- All timestamps use DateTime.UtcNow - never DateTime.Now
- Migrations exist and are up to date for every service
- Each service has its own isolated database (no shared DB between services)


REUSABILITY
-----------
- No duplicated mapping logic - MapToDto() is a private static method in the service
- PagedResult<T> and ServiceResult<T> are not duplicated - one copy per service (or move to Shared.Contracts)
- Middleware classes (ExceptionMiddleware, SecurityHeadersMiddleware) are identical across services - consider moving to Shared.Contracts
- ClaimsPrincipalExtensions is identical across services - consider moving to Shared.Contracts
- Filter DTOs (XFilterDto) always include Page and PageSize with defaults


API DESIGN
----------
- All routes are lowercase and kebab-case (api/postal-codes not api/PostalCodes)
- HTTP verbs are used correctly: GET read, POST create, PUT/PATCH update, DELETE delete
- POST returns 201 Created with CreatedAtAction
- DELETE returns 204 No Content on success
- Validation errors return 400 Bad Request
- Not found returns 404 Not Found
- Ownership/permission failures return 403 Forbidden
- No business logic lives in controllers - only call service, return result


PROGRAM.CS
----------
- Middleware order is correct: ExceptionMiddleware > SecurityHeaders > HTTPS > Authentication > Authorization > Controllers
- Swagger is only enabled in Development environment
- AddInfrastructure() is called to register all dependencies
- Authentication and Authorization are both registered and used
